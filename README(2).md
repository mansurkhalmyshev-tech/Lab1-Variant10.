## Теоретическое обоснование

**Клиент-серверная архитектура.** Взаимодействие в вебе построено по модели «клиент — сервер». Клиент (браузер, мобильное приложение) формирует HTTP-запрос и отправляет его на сервер. Сервер (бэкенд-приложение) принимает запрос, выполняет бизнес-логику и возвращает HTTP-ответ: код состояния, заголовки и тело. Бэкенд работает на стороне сервера и напрямую пользователю не виден — клиент получает только результат обработки.

**Эндпоинты и маршруты.** Эндпоинт — это конкретный адрес (URL) вместе с методом HTTP, по которому клиент обращается к серверу за ресурсом, например `GET /api/events`. Маршрут (route) — механизм сопоставления пути и метода запроса с функцией-обработчиком на сервере. В Express маршруты задаются методами вида `app.get(path, handler)`, а промежуточные обработчики (middleware) подключаются через `app.use()` и выполняются до обработчика маршрута.

**HTTP и JSON.** HTTP — основной протокол передачи данных в интернете. Метод GET используется исключительно для получения данных и не должен изменять состояние сервера. Ответ содержит код состояния: `200 OK` при успехе, `404 Not Found`, если ресурс не найден. Тело ответа часто передаётся в формате JSON — текстовом формате обмена данными, ставшем стандартом де-факто для REST API. В Express метод `res.json(obj)` автоматически сериализует объект в JSON и устанавливает заголовок `Content-Type: application/json`.

**Стек и автоматический перезапуск.** Node.js — платформа, позволяющая выполнять JavaScript вне браузера, на сервере. Express — минималистичный веб-фреймворк для Node.js, упрощающий маршрутизацию и формирование ответов. При активной разработке код часто меняется, поэтому вместо ручного перезапуска используют `nodemon` — утилиту, которая следит за файлами проекта и автоматически перезапускает сервер при их изменении.

const express = require('express');
const app = express();
const port = 3000;

// 1. Текстовый эндпоинт (корневой)
app.get('/', (req, res) => {
    res.send('Сервер работает');
});

// 2. JSON эндпоинт 1: События
app.get('/api/events', (req, res) => {
    res.json([
        { id: 1, name: "Конференция по веб-разработке", date: "2024-05-15" },
        { id: 2, name: "Хакатон", date: "2024-06-01" },
        { id: 3, name: "Встреча выпускников", date: "2024-07-20" }
    ]);
});

// 3. JSON эндпоинт 2: Локации
app.get('/api/locations', (req, res) => {
    res.json([
        { id: 1, city: "Москва", venue: "Крокус Экспо" },
        { id: 2, city: "Санкт-Петербург", venue: "Ленэкспо" },
        { id: 3, city: "Казань", venue: "Казань Экспо" }
    ]);
});

// 4. Обработка 404 (Not Found)
app.use((req, res) => {
    res.status(404).json({ error: "Not Found" });
});

// Запуск сервера
app.listen(port, () => {
    console.log(`Сервер запущен на http://localhost:${port}`);
});

Контрольные вопросы
1. Что такое клиент-серверная архитектура?
Это модель организации взаимодействия, при которой клиент (браузер, мобильное приложение) инициирует запрос, а сервер принимает его, обрабатывает и возвращает ответ. Клиент отвечает за представление данных и интерфейс, сервер — за бизнес-логику, хранение данных и безопасность. Клиент и сервер — независимые программы, которые общаются по сети через стандартный протокол.

2. Какой протокол используется для общения клиента и сервера в вебе?
HTTP (HyperText Transfer Protocol). Это протокол прикладного уровня, работающий по схеме «запрос — ответ». Каждый запрос независим от предыдущего (протокол stateless). Для шифрования трафика применяется HTTPS — тот же HTTP поверх TLS.

3. Что такое эндпоинт (endpoint)?
Эндпоинт — это адрес (URL), по которому клиент может обратиться к серверу за определённым ресурсом, в сочетании с HTTP-методом. Например, GET /api/events и POST /api/events — это два разных эндпоинта с одним путём. В коде эндпоинт реализуется маршрутом: путь + метод + функция-обработчик.

4. Какую структуру имеет HTTP-запрос и HTTP-ответ? Что такое код состояния?
HTTP-запрос состоит из: строки запроса (МЕТОД /путь HTTP/1.1), заголовков, пустой строки и необязательного тела. HTTP-ответ состоит из: строки статуса (HTTP/1.1 200 OK), заголовков, пустой строки и тела ответа. Код состояния — трёхзначное число, сообщающее результат обработки (200 — успех, 404 — не найдено, 500 — ошибка сервера).

5. Что такое JSON? Почему он популярен в веб-разработке?
JSON (JavaScript Object Notation) — текстовый формат обмена данными, основанный на синтаксисе объектов JavaScript. Популярен потому, что он компактен, легко читается человеком, нативно парсится в JavaScript без дополнительных библиотек и поддерживается практически любым языком программирования.

6. Как запустить сервер на Node.js?
В каталоге проекта выполняются команды:

bash
npm init -y
npm install express
node app.js        # обычный запуск
npm run dev        # запуск под nodemon
После вывода Сервер запущен на http://localhost:3000 сервер доступен по адресу. Остановка — Ctrl+C.

7. Что такое автоматический перезапуск сервера и зачем он нужен? Какой пакет используется для Node.js?
Автоматический перезапуск (hot reload) — режим, при котором сервер сам перезапускается после сохранения изменённого файла, без ручной остановки. Это экономит время при разработке. Для Node.js используется пакет nodemon, устанавливаемый в dev-зависимости и запускаемый скриптом "dev": "nodemon app.js".

8. Какие коды состояния HTTP вы знаете? За что отвечает код 404?
Основные: 200 OK — успех, 201 Created — ресурс создан, 301 Moved Permanently — редирект, 400 Bad Request — некорректный запрос, 401 Unauthorized — не аутентифицирован, 403 Forbidden — доступ запрещён, 404 Not Found — ресурс не найден, 500 Internal Server Error — ошибка на сервере. Код 404 Not Found означает, что сервер не нашёл ресурс по указанному URL.

9. Что такое middleware в Express?
Middleware — функция с сигнатурой (req, res, next), которая выполняется в цепочке обработки запроса до финального обработчика маршрута. Она может читать и изменять req/res, выполнять логирование, проверку авторизации. Чтобы передать управление дальше, middleware вызывает next(). В работе обработчик 404 — это тоже middleware, подключённое последним.

10. Как получить параметр из URL-пути (например, ID пользователя)?
В Express параметр задаётся в шаблоне маршрута с двоеточием и читается из req.params:

javascript
app.get('/api/events/:id', (req, res) => {
  res.json({ requestedId: req.params.id });
});
Запрос GET /api/events/5 даст req.params.id === '5'.
